From Whisper Cold Starts to Native GPU Inference

How persistent Whisper processes and native Vulkan inference cut offline transcription time by 2.7x.

Real-time captions used to launch whisper-cli for every transcription window. Each run started a process, reloaded the model, wrote a WAV file, and returned a result. That overhead made captions slower than the speech recognition itself needed to be.

The bottleneck was startup work

The first change replaced process-per-chunk execution with a persistent whisper-server sidecar. The model loaded once when the sidecar started, then the app sent in-memory WAV audio to a local HTTP endpoint for each inference. The CLI path remained available when the server was unavailable.

Median caption lag
936 ms → 686 ms
CPU improvement
27%

Removing repeated startup and model loading reduced median caption lag on the CPU base-model benchmark by 27%, while audio-buffer flushing continued to avoid uncovered audio and buffer overflows.

Remove the process boundary

The next step removed the HTTP boundary altogether. The Electron sidecar uses Koffi FFI to load whisper.dll directly, keeping the model loaded in the native Whisper context and passing floating-point PCM directly to Whisper. This path includes Vulkan GPU inference.

Measure the end-to-end result

The first Vulkan measurement on an RTX 3060 Ti transcribed 30 seconds of audio in 115 ms, or about 259x faster than real time for raw steady-state inference. The end-to-end comparison is the more useful number: the native FFI Vulkan path completed offline transcription in 1,044 ms versus 2,824 ms for the CLI.

Offline transcription
2,824 ms → 1,044 ms
End-to-end improvement
2.7x faster

Keep the model ready

The architecture changed from “start Whisper for every caption” to “keep Whisper loaded and ready.” The result is lower caption lag, less CPU and disk overhead, and a path to native GPU transcription without changing the meeting app’s caption protocol.
